# pass-slice

- `WORKFLOW_PAUSED` is a durable operator boundary. Stop without bypassing it, requesting continuation, cancelling the workflow or recording a failed source. A boundary owner with an already durable result may submit only `worker-complete`; the trusted reconciler acknowledges that result while holding successors.

- Worker commands commit Vault results only. A response with `kanban_reconciliation_pending` leaves Kanban completion, failure status and successor dispatch to the trusted workflow reconciler. Do not invoke `hermes kanban` from this worker terminal or remove Hermes isolation markers.

- Dispatcher: use the absolute `dispatcher_script` from the card. Lease this slice with `python3 "<dispatcher_script>" --vault "<vault>" worker-begin --request "<worker_binding>" --request-output "$HERMES_KANBAN_WORKSPACE/worker-request.json"`. This CLI writes the complete checked Pass request as real JSON inside the worker workspace before it returns. Use that file for worker-check, domain writes, worker-heartbeat and worker-complete. Extend the lease with `worker-heartbeat --request "$HERMES_KANBAN_WORKSPACE/worker-request.json" --request-output "$HERMES_KANBAN_WORKSPACE/worker-request.json"`; the CLI atomically refreshes the revision in the same file. Never write, copy, or patch the binding JSON yourself, invent `lease_revision`, copy `worker_template_hash`, or reconstruct identity from environment variables. Stop if either CLI fails.
- Stop immediately on failed worker-check or heartbeat, cancellation, stale binding or template mismatch. Do not import internal services to bypass a failed command, resume/cancel the whole workflow, alter pinned contracts, or clear worker environment variables. Report runtime/contract failures on this card; they are not evidence of damaged source material.
- Check the lease with `python3 "<dispatcher_script>" --vault "<vault>" worker-check --request "$HERMES_KANBAN_WORKSPACE/worker-request.json"`. An optional `--request-output` copies the same validated binding inside the workspace; it does not renew the lease or advance its revision. Only `worker-heartbeat` renews the lease. Do not pass `--request-output` to worker-complete or worker-fail.

- Role / sole objective: finish exactly the named Vault slice with ordinary Pass evidence.
- Allowed inputs: only the claimed slice's task snapshots and listed bounded reading packages/UnitRefs; open no other batch readings.
- `worker-begin` prepares only the leased slice and returns `task_snapshots` plus `reading_packages` containing task_id, reading_package_id and Vault-relative path. Read those package files. Use their document_registry_revision and the returned task revisions; do not call batch-prepare or scan task directories.
- Allowed commands: `dispatch_ingest_workflow.py worker-begin`, `worker-check`, `worker-heartbeat`, `worker-complete` or `worker-fail`; controlled-ingest `manage_knowledge_build.py batch-pass` for each leased task.
- Persist semantic Pass JSON with `python3 "<domain_script>" --vault "<vault>" --worker-binding "<workspace binding request>" batch-pass --request "<Pass JSON>"`. Use the absolute domain_script from the card and the binding's actor. The binding flag is required in the isolated terminal. Read only the returned slice's task snapshots and bounded package files. Record candidate sequence 0 and citation sequence 1 against current task revisions; an empty candidate set still requires a grounded inspection and an explicit empty_reason. The model performs these inspections; never synthesize completion from an empty template.
- Build references by copying complete source_ref/span objects from the returned reading package with a JSON script. Never retype, shorten or reconstruct resource/UnitSet/unit hashes. Before each write run the same bound `batch-pass` command with `--validate-only`. It validates schema, current identity, sequence, reading coverage and live references without writing Pass/task/batch records. Persist only after `ok: true`, using the identical draft. For an `INVALID_SCHEMA` in your own draft, retain it and its diagnostics in the worker workspace, correct only that draft from the schema and observed package references, and preflight again at most twice while maintaining the lease. Never fix a binding, source or ledger; stale input, stopped lease, changed evidence and WORKFLOW_PAUSED require immediate stop. An unresolved or repeated preflight failure must be reported with the saved draft and diagnostics, not bypassed.
- The batch-pass request is `{"batch_id":"<slice batch>","passes":[{"task_id":"<leased task>","actor":"<binding actor>","expected_revision":0,"registry_revision":0,"reading_package_id":"<returned package>","pass_kind":"candidate","sequence":0,"inspections":[],"candidates":[],"empty_reason":""}]}`. Replace revisions with observed integers and populate evidence. Each inspection has source_ref (the full UnitRef/span object), finding, qa (`usable` or `needs-qa`) and qa_note. Each candidate has candidate_id, name, kind (`entity`, `concept`, `requirement`, `fact` or `analysis`), identity_rationale, finding, applicability, conditions (strings), exceptions (strings), support_refs (full source references). The citation pass uses sequence 1 and pass_kind `citation`; use the task revision returned by the candidate write, inspect support and carry forward the supported candidates. Do not invent identity fields or submit these empty illustrative arrays without inspecting the materials.
- Fixed IDs / hashes: workflow ID, Kanban task ID, batch ID, slice ID, task IDs, slice input fingerprint, pinned slice template ID/hash, lease worker ID and expected revision must match on every write.
- Bounds: one slice; obey exact reading windows and model budget; finish the current slice then exit.
- Heartbeat: maintain both Vault `slice-heartbeat` and Kanban heartbeat before lease expiry; no work without a Vault lease.
- Output JSON schema: `{"ok":boolean,"workflow_id":string,"slice_id":string,"pass_ids":string[],"lease_revision":integer,"error_code":string|null}`.
- Complete only after initial and subsequent Pass records are durable, `worker-complete` verifies them and the Kanban task can be marked done. On an unresolved draft error after bounded preflight correction, or any runtime/identity failure, call `worker-fail` with the raw failed output. Never silently substitute a different citation or discard a failed inspection to make validation pass.
- Prohibited: plan, prepare, Reduce, Finalize, release, approval, scanning the whole batch or changing the slice-pinned template hash.
- In `auto_full`, the dispatcher arms exactly eight initial slices, promotes the remaining slices only after those eight have valid durable Pass results, and continues to Reduce after every slice completes. A worker still processes only its assigned slice.
