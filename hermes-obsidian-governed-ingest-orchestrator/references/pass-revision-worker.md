# Append-only citation revision worker

Use the card's dispatcher_script, domain_script and canonical worker_binding. Run worker-begin with --request-output "$HERMES_KANBAN_WORKSPACE/worker-request.json"; use this checked binding for worker-check, heartbeat, every domain call and worker-complete. Never reconstruct or modify the binding. Maintain the lease. Stop on stale input, cancellation, failed binding or heartbeat. Do not operate Kanban from a worker terminal.

This is a selected semantic revision under a held pause. The dispatcher explicitly permits only this revision; do not continue, cancel or resume the workflow. No source preparation, exact planning, Reduce or Finalize.

worker-begin returns only the selected task_snapshots, bounded reading_packages and pass_revision.tasks. Each target names its predecessor pass_ref, reason and authorized next sequence. Read those predecessor citation files and the returned bounded packages only. Preserve supported candidates from the predecessor; revise incorrect findings, conditions, exceptions and applicability or explicitly remove unsupported claims with a grounded reason. Recheck every claim against its actual supporting text. Any use of context material, including a clause continued across a window boundary, needs that complete source_ref in support_refs and a corresponding inspection. Do not copy an aggregate conclusion while citing only the core fragment. Inspect actual material; do not add references mechanically based on proximity, titles or keywords.

Submit one complete replacement citation for each selected task: pass_kind=citation, sequence from the target, reading_package_id from the target, current task revision and package registry revision, binding actor, grounded inspections, reviewed candidates and an explicit empty_reason if needed. Copy full source_ref/span objects from the bounded package. Preserve other valid candidate findings unless a semantic correction is needed. Never write candidate sequence 0 or alter historical Pass files. The runtime records revision_id and supersedes_pass_id from the authorization; do not fabricate them.

Before each write execute python3 "<domain_script>" --vault "<vault>" --worker-binding "$HERMES_KANBAN_WORKSPACE/worker-request.json" batch-pass --request "<draft>" --validate-only. Inspect ok, validated, failures and exact Pass IDs. Persist only the identical successful draft using the same bound command without --validate-only. Save drafts and diagnostics in the workspace; bounded correction of your own schema errors is allowed, never contract bypass. Stop and report unresolved errors. Heartbeat before lease expiry, using --request-output to refresh the checked binding.

Finish with worker-complete only after all selected new citations are durable. Other tasks in the same slice remain unchanged. The trusted reconciler retains the canary/pass pause, refreshes its evidence and waits for reviewer acceptance. Do not submit acceptance or continuation.
