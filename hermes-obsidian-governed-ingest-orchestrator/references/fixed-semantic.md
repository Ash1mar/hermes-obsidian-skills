# Fixed semantic execution

Recovery reuses authenticated native packet boundaries instead of rerunning the
greedy boundary search for each successful prefix packet. It reconstructs the
complete current input/directory and previous state, then uses the same native
transcript proof, exact schema/wire, coverage and cumulative validator. Original
failure records, attempt ordinals and correction wires remain unchanged. This is
a pure reconstruction optimization shared by execution and recovery preview,
not a new recovery authorization, stored-state acceptance or permission cache.

Only uncalled global planning adopts reader-topic/v1. A page should form an
independently readable and retrievable topic; source groups, schedule intervals,
directory pieces and figure fragments are not mandatory page boundaries. Same
resource/version plus an exact full supported heading path can expose a related
planned page for comparison. Headings are navigation only, not proof that claims
are equivalent, that required evidence exists or that merging is safe. Model
decisions still preserve all conditions, exceptions, conflicts, scope and QA.
Every expanded directory and rule is measured in the complete request budget.
Consumed legacy/short packets are selected first; neither topic guidance nor
boundary reconstruction can mint a new allowance or rewrite their input.

Independent body execution uses two slots at most (or the lower configured
capacity), under the same native task. A body owns a separate caller/SessionDB,
adapter and context-local attempt; only progress publication shares a lock.
Planning/refinement drains pending bodies before changing identities or issuing
another model request. Local holds remain isolated; shared authority/transport
failures stop admission and drain. Existing output-boundary recoveries, if any,
retain their single-request behavior; this never creates a new pause or retry.

Native JSON-object output mode prevents free Markdown and invalid JSON escapes
for non-slot phases; task slots retain their strict transport schema. Canonical
schemas, prompts, evidence and view identities remain unchanged, so old answers
and consumed attempts keep their original validation and allowance. API JSON
syntax enforcement is not a semantic approval or evidence repair. During saved
response authentication, the immediately preceding execute-entry check supplies
the first authority check; fresh exit checking remains mandatory.

Pinned `hermes-fixed-semantic/v1` templates select the native semantic executor.
The trusted reconciler grants the same native claim/run/PID lifecycle used by
program nodes. Installation does not change old workflow pins or release pauses.

Pass executes candidate extraction followed by a separate citation review.
The program resolves tN/mN identities, refreshes its own checked lease, assigns
sequence numbers, validates and persists results, then completes the worker.
The model must actually review candidates and original QA before confirming;
changed facts, conditions or support require only changed/new candidate entries,
removed candidate IDs and changed inspections. The program merges them into the
exact observed original and subjects the complete result to existing validation.
Citation checks source fidelity and important omissions, not grouping or prose
polish. Unchanged entries are retained; an absent review is never approval. Already valid
partial Passes are preserved. A rejected semantic draft permits one bounded
correction for the failed scope. Stale evidence, cancelled grants, unavailable
bindings and material contract failures end execution without automatic rebind.

Resource Reduce receives current citation semantics and inspection QA. Global
Reduce additionally receives resource proposals and checked existing pages.
Only exactly identical semantics and QA share a cN handle. The program expands
all originals, checks complete adopt/omit coverage and current input hashes,
assigns revisions/run identities and submits under the existing workflow guard.
Exact existing identity determines create/update; the model determines meaning,
identity hints and page content. Global planning always uses the complete compact
identity directory and source proposals with candidate routing scope, conditions,
exceptions and QA boundaries. It does not receive raw reading packages or repeated
candidate findings. This is provisional routing, not factual equivalence or approval.
Planning uses table rows with explicit field columns and a shared QA dictionary to
remove repeated keys and identical QA values. Scope, conditions, exceptions, proposal
membership and identity/path hints are retained exactly; full readings stay unchanged.
Each planned page is then written using its full selected original evidence and exact
checked parent, including when there are no existing pages. Writing verifies the
proposed grouping and preserves source/version differences; incompatible identities
remain blocked. Each complete page request is budget-checked before its body call.
An oversized provisional page uses the existing global-detail task and finite
output journal to select narrower semantic identities with exact candidate
coverage and measured complete body inputs. Originals, conditions and QA are
never truncated. Only affected pages are reconsidered; successful planning is
replayed unchanged. This adds no worker node, phase or recovery scope.

Page-local budget, material or finite-output holds are recorded while other
ready pages continue. Even a held later planning packet allows native bodies for
the already valid provisional prefix, without claiming whole-batch coverage.
Native Markdown is persisted under the workflow's page-drafts directory with
exact input/audit references; valid unchanged bodies reuse their normal journal.
Final global submission still requires complete plan coverage and every page's
valid body. Source/hash/authority changes remain fatal. Build Finalize follows
the same local-hold rule, preserving independent valid reviews before holding
finalization; its separate authorization and checkpoints are unchanged.
No fuzzy partition silently separates
conflicting candidate semantics; an oversized indivisible plan still blocks.

Resource calls produce concise proposals only. Existing `candidate_refs` record exact
membership; `summary` names the group and necessary applicability/condition/conflict/QA
boundaries, and `identity_hints`/`path_hints` remain suggestions. They do not write page
bodies or repeat candidate findings. Full necessary original evidence remains available.
Global coordination starts from those proposals and preserves compatible groups by default.
It resolves cross-proposal equivalence, conflict, scope and identity differences, including
packets from the same source. When splitting, merging or omitting a proposal, the existing
`reason` names the affected pN handles and concrete grounds. Page writing and the one later
substantive page review retain their existing evidence and coverage contracts. There is no
new schema, routing layer or automatic semantic approval; program coverage validation does
not prove the model's grouping reasons correct.

Build Finalize now reviews one owned draft page per fixed call against citation
facts/QA and its verified parent. The model returns only a semantic decision and
actual review note. The program binds all page/run hashes and rechecks the entire
observed input before serial finalization. Rejected or stale reviews cannot count
as approval. Checkpoints and release gates still apply.

第四步仅收紧这一次独立页面审阅的拒绝标准：事实、精确数值及单位、AND/OR、范围、条件、例外、冲突、必要覆盖和既有内容保留。拒绝说明具体受影响的主张或遗漏要求；措辞偏好、排版和可选润色不构成拒绝、重写或再审理由。模型仍只返回decision/review_note，不写正文。合法的实质拒绝继续持有，不由通用输出纠正机制强迫通过；只有JSON/schema等机械输出合同错误才适用共同的一次纠正额度。保留原有先逐页审阅、再统一提交及哈希复核边界，不增加专门页面审阅缓存。共用原生调用账本的严格重验复用不等于事实批准，也不提前发布页面。

Each model invocation is a one-turn native Hermes session with no tools, Skill
lookup, context files, memory or fallback agent. Its instructions, JSON schema,
evidence and correction all count toward the input bound. No material is silently
truncated; an oversized task is held for supported input planning. The native
request boundary checks the actual outgoing system/user messages and zero tools;
it excludes Hermes' general agent scaffold as well as Skill/context injection.
Pass views contain only the current phase, used texts/headings/QA and original
material permissions, without program sequences/continuation instructions.
Read-only identity expansion happens before the shared workflow commit lock;
live lease, source, ACL, revision and persistence checks still run under the lock.
Call audits measure input/static codepoints and elapsed model time. These counts
and basic checks do not establish full semantic acceptance or total cost savings.

Calls use the SDK's context-local delegated-child scope in the owning program;
no per-call subprocess or process-wide identity changes are needed. Model turn
finalization cannot terminate the parent card. Native execution identity, lease
settlement and durable completion remain program responsibilities. The trusted
reconciler settles a terminated current run's exact lease before selecting new
capacity, using the existing failure transition and retaining partial results.

Semantic call audits link actual native session/output hashes to program receipts
and bound preflights. Acceptance checks real transcripts and persisted Passes;
it does not require a model execution-tool call or count fixtures as native proof.
An unexpected exception is recorded for operator diagnosis, not routed to an
open agent inside the worker. Existing pause and separate authorization rules apply.

Pass return keys are fixed by the program. Strict structured schema is sent at
the Responses/Chat boundary, counted in the input budget, and not copied again
into prompt text. Local canonical validation remains authoritative. Missing or
invalid slots cannot complete a slice; valid slots are submitted once and only
affected slots receive the bounded correction. Duplicate JSON keys are rejected.

Image count and total bytes are configured in `config/orchestration.json`.
Whole evidence remains intact; oversize reports include actual count, total and
largest bytes plus configured limits. This local budget is not a claim about all
providers' capacities; native acceptance must establish the active route.

Shared lock owners and independent host diagnostics record PID, operation, wait,
hold time and exit reason. Preparation measures outside the workflow commit lock
and rechecks snapshot signatures and current task/lease authority before writes.
Heartbeats check lifecycle identity without rebuilding semantic input; submission
still validates live source/ACL and canonical output. Genuine audited responses
can be reused only for the same task with identical fresh input and instructions,
with original native provenance linked explicitly and current bound preflight.

The program derives whether a merged citation is empty. For a nonempty result,
the canonical empty-reason field is empty without requesting another semantic
generation; an actually empty result still needs the model's genuine reason.
Delta validation failures remain local to their slot. Other valid slots are
submitted before requesting correction, while stale authority stops execution.

Bound groups retain the existing partial-result contract. The shared workflow
lock is released after each individual Pass and its preflight, with the current
lease/cancellation/source checks repeated before the next commit. A later lock
or authority failure retains previous successful receipts in the audit. The
atomic domain unit is unchanged; there is no new group transaction or retry layer.

## 定向恢复与增量全局规划

- `recover-reduce-execution` 的 `source-format/v1` 只用于已认证原生响应确实不可解码、且当前失败含该 schema 拒绝的来源。钉住快照/失败/审计 SHA 和运行绑定，原响应不修改；仅给缺失格式包一次新的原生机会，精确成功包继续复用。语义拒绝、合法 JSON 的领域问题不能借用此范围。
- `dependency-resolved/v1` 只解除 `DEPENDENCY_EXECUTION_BLOCKED` 派生持有。必须核对其记录父节点属于当前依赖、全部父依赖均有有效完成证据、当前最新 citation 的完整必读材料与 inspection、接受修订和明确排除的覆盖；接受标签本身不放行。恢复报告保存旧失败、当前父证据和排除/修订摘要。既有父任务、有效 citation、明确排除及正式来源成果不重跑。
- 先缩小职责，再分包：`global-plan` 默认只读取提案主题、共享身份建议、版本/来源、非 usable 的实质风险和成员数量，不携带全部候选明细、成员引用或普通 inspection 叙述。模型返回完整 `proposal_refs` 路由；程序展开候选并检查恰好一次覆盖。来源分组默认复用，规划不承担 citation 再审阅或事实批准。
- 只有具体拆组、冲突或身份歧义才返回本包的 `detail_unit_refs`，并说明原因。程序为所请求的不可分单元提供一次有界 `global-detail` 候选明细；其他提案不补读。这一步不能排除候选、反复查询或索取原文作全面审阅；不能解决时保持分开或持有。最终逐页写作才核对完整必要证据。
- 按稳定顺序累加提案，共享候选的提案保持同一不可分单元。完整请求上限30000 codepoint，沿用8192输出预算按每页256 token、预留1024作固定估算，每包至多28提案；不是模型输出长度保证，不可分超限仍持有。程序按身份键/名称/别名缩小相关目录，只提供比较范围，不决定语义合并。追加既有规划页必须使用提供的精确身份和路径，保留版本及适用条件差异；相关前序页面只带主题及来源，不重复全部成员边界。
- 每包成功原生审计绑定精确输入、前序累计状态 SHA，成功状态可在后续失败/停止后严格复用。汇总只做完整覆盖、重复候选、身份和路径冲突检查；不追加携带全部材料的模型调用。机械空状态装包检查不代表未来相关页面加入后仍可容纳；运行时逐包重新计量。
- 页面正文仍逐页读取完整必要证据及哈希有效旧页；所有正文请求先计量后调用，不以摘要替代证据。通过后提交到原有 checkpoint_1，Build Finalize、页面审阅、发布及 Provider 同步保持其独立暂停授权。
- 效率比较固定同一批来源成果，计量全部默认规划与按需细节调用的累计完整输入、重复材料和新增判断。机械空状态分包是容量比较，不能声称真实模型成本已下降；不能仅凭单包变小或调用成功验收效率。来源阶段暂不删原文保障，不改变有效来源成果。

来源归并、全局规划/明细、写作和页面审阅的 JSON 输出共用 finite-semantic-output/v1。校验位置确认的 schema、覆盖、互斥选择和输出目标错误最多获得一次带精确诊断的原生纠正；原始失败和每次原生身份不覆盖。页审阅决定要求修订、证据不足、QA、事实冲突、绑定/权限/哈希和传输问题均不因此获得纠正。逻辑包、原始输入及前序状态决定持久次数；换提示、worker或重启不重置。响应已落盘则完整重验并复用；调用结果不确定则先核对原生 session，禁止盲目重发。两次仍失败持有，不增加审阅层、自动调参或新调度框架。

尚未调用的全局规划/明细包采用 global-target-refs/v1：已提供的既有或临时页面各有本包局部 target_ref，模型选择引用，程序展开原精确身份、别名和路径。新页面仍由模型提出语义身份和路径；相关不等于可以合并，目录外引用、重复或缺失覆盖继续拒绝。原始响应保留，完整累计诊断和默认一次纠正不变。

历史包先按原始 view 查找持久次数账本及明确恢复 seed；存在旧记录时保留原规则、schema、输入和次数，不升级或重写响应。只有没有旧消费记录的新包采用短引用；同一逻辑包发现两个合同的消费记录则持有，不能靠换 schema 获得新次数。每次实际请求仍完整计量，超限持有。

短引用使用同一输出schema贯通原生解码、机械校验和恢复证明。已拒绝的原始回答不改写；只有尚未消费的纠正请求可采用新诊断。对短引用包，诊断保留完整累计检查，只发送实际冲突的索引摘录、完整覆盖问题及原响应SHA；模型从未变的完整输入返回完整替代回答，摘录不是被接受的部分成果。超预算不截断原文或调高上限。两次额度耗尽继续持有，额外第3次必须经现有入口、精确原生证明和用户单独明确授权，不能靠修补或换合同重置次数。
