# Fixed semantic execution

Pinned `hermes-fixed-semantic/v1` templates select the native semantic executor.
The trusted reconciler grants the same native claim/run/PID lifecycle used by
program nodes. Installation does not change old workflow pins or release pauses.

Pass executes candidate extraction followed by a separate citation review.
The program resolves tN/mN identities, refreshes its own checked lease, assigns
sequence numbers, validates and persists results, then completes the worker.
The model must actually review candidates and original QA before confirming;
changed facts, conditions or support require a revised draft. Already valid
partial Passes are preserved. A rejected semantic draft permits one bounded
correction for the failed scope. Stale evidence, cancelled grants, unavailable
bindings and material contract failures end execution without automatic rebind.

Resource Reduce receives current citation semantics and inspection QA. Global
Reduce additionally receives resource proposals and checked existing pages.
Only exactly identical semantics and QA share a cN handle. The program expands
all originals, checks complete adopt/omit coverage and current input hashes,
assigns revisions/run identities and submits under the existing workflow guard.
Exact existing identity determines create/update; the model determines meaning,
identity hints and page content. When existing pages exist, global planning uses
their complete compact identity directory, then writes each planned page using
only its selected evidence and exact checked parent. With an empty directory the
single global call remains sufficient. No fuzzy partition silently separates
conflicting candidate semantics; an oversized indivisible plan still blocks.

Build Finalize now reviews one owned draft page per fixed call against citation
facts/QA and its verified parent. The model returns only a semantic decision and
actual review note. The program binds all page/run hashes and rechecks the entire
observed input before serial finalization. Rejected or stale reviews cannot count
as approval. Checkpoints and release gates still apply.

Each model invocation is a one-turn native Hermes session with no tools, Skill
lookup, context files, memory or fallback agent. Its instructions, JSON schema,
evidence and correction all count toward the input bound. No material is silently
truncated; an oversized task is held for supported input planning. The native
request boundary checks the actual outgoing system/user messages and zero tools;
it excludes Hermes' general agent scaffold as well as Skill/context injection.
Pass views contain only the current phase, used texts/headings/QA and original
material permissions, without program sequences/continuation instructions.
Read-only identity expansion happens before the shared workflow commit lock;
live lease, source, ACL, revision and persistence checks still run under the lock.
Call audits measure input/static codepoints and elapsed model time. These counts
and basic checks do not establish full semantic acceptance or total cost savings.

Semantic call audits link actual native session/output hashes to program receipts
and bound preflights. Acceptance checks real transcripts and persisted Passes;
it does not require a model execution-tool call or count fixtures as native proof.
An unexpected exception is recorded for operator diagnosis, not routed to an
open agent inside the worker. Existing pause and separate authorization rules apply.
