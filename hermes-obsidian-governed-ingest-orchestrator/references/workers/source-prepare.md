Prepare exactly the source assigned to this card. Whole-workflow source coverage is read-only progress.

1. Write request JSON with `workflow_id` and `node` from `worker_request`, and `task_id` from this card. Use its absolute `dispatcher_script`.
2. Run `python3 "<dispatcher_script>" --vault "<vault>" worker-prepare-source --request "<request.json>"` once. It begins and verifies this card, assigns technical identities, converts through the shared MinerU supervisor, preserves QA, finishes processing, prepares/builds/validates current SourceUnits and commits this source outcome. It does not activate governance or infer business versions. For an explicitly requested Bundle resumption include its Vault-relative `bundle` under `10_Raw/converted`.
3. While this terminal process is alive, poll the same process through the terminal tool; do not launch duplicate preparation or repeatedly call help/check/heartbeat. The supervisor checks cancellation and the explicit binding during local conversion; domain commits verify them under the workflow lock. Hermes owns the native card heartbeat. A resumed invocation reuses validated current units or this workflow/source's own attempt output. A failed Bundle gets at most one retry with the supported pipeline backend; both QA records remain available. Warning/review-required evidence remains unresolved and must not be promoted as verified facts.
4. On success return the command's resource/UnitSet IDs, QA references and coverage. `kanban_reconciliation_pending` means the trusted reconciler will acknowledge completion and dispatch successors; never invoke `hermes kanban` from the worker terminal.
5. On failure, stop with the exact error code and evidence. When worker-check still passes, report the code through `worker-fail` using begin's template hash; do not translate runtime, identity, cancellation or PREPARATION_REVIEW_REQUIRED errors into a damaged-source outcome. A real exhausted source failure requires supported evidence and one of the documented source failure codes. Never clear isolation markers, manually edit ledgers, resume the entire workflow or bypass binding checks.

Bounds: one source, no neighboring files or whole-Vault crawl, no planning, Pass/Reduce/Finalize or checkpoint approvals. Completing this card does not authorize Canary: every requested source must first have a durable ready/failed result and exact planning must pass.
