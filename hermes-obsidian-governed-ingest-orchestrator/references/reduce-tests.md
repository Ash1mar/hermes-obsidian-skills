# Same-workflow Reduce supplemental tests

This is an explicitly authorized test entry, never the formal ingest startup or
ordinary resume operation. It keeps the same physical Vault, workflow, batch,
source identities, immutable original evidence, completed slices and native Pass
results. Do not implement a cross-workflow/Vault adoption for this entry.

Only a terminal, drained `auto_full` workflow in a test security domain with Query
disabled and no durable pauses is eligible. All planned Pass slices must have
genuine native Citation/preflight evidence. Saved Resource Reduce inputs must
authenticate every pre-Reduce task and its exact Pass hashes. Changed sources,
unproved task preimages, outstanding workers, leases or runnable cards block
admission. Skipped/revised Pass scopes currently return an explicit unsupported
boundary instead of silently changing coverage.

The entry retires the old Reduce/Build/publication control and page outputs into
an immutable, hash-inventoried **Vault data audit**, and restores the authenticated
pre-Reduce task and source-governance boundary. It does not back up old code.
The old Provider generation remains host-side replaceable data until the new
publication sync; Query stays disabled. Both checkpoints, initial publication
qualification, Provider synchronization and Final Acceptance execute normally.

The same operation ID admits exactly once. A crash during retirement/restoration
replays its journal; retrying a running or finished cycle cannot retire results or
mint allowance again. An explicit later cancellation or durable pause stays held.
New downstream native card identities include the test operation; Pass identities
do not change. The new cycle pins the current unified page protocol before calls.

This is an authorized **retest**, not zero-call restoration of valid downstream
results. Original Pass budgets remain in place. Old downstream request budgets,
responses and receipts remain in the retired audit. Report the newly authorized
cycle separately and include old/new calls in cumulative totals. Restart/recovery
within the cycle never resets its per-page initial/one-additional allowance.

First create a read-only, hash-pinned request (no model or dispatch):

```bash
python3 "<skill-dir>/scripts/start_reduce_test.py" --vault "<vault>" \
  --workflow-id "<same-workflow>" --operation-id "<stable-test-operation>" \
  --plan --request "<external-request.json>"
```

Then perform the authorized test reentry and handoff:

```bash
python3 "<skill-dir>/scripts/start_reduce_test.py" --vault "<vault>" \
  --request "<external-request.json>" --record "<external-receipt.json>"
```

`--dry-run` checks the affected contract without retiring data or starting work.
Observe in the current operator task every five minutes; do not schedule a job or
make repeated model requests just to poll status. Compare Reduce and downstream
stages only, accounting for coverage/output changes, genuine two-result receipts,
model waiting, program waiting and maintenance separately. No benefit is established
merely by deployment, a request returning, or total wall time.
