# Build evidence disposition

`build-evidence-disposition/v1` is generated by the native program worker after
checking every page. It prepares authenticated ready reviews and separately
defers revision opinions, explicit refusals, completion unknowns and unproven
stopped attempts. Content-addressed inventories preserve previous reports and
link the exact input snapshot, candidate ownership, page revision, original
packet, finite journal, wire hashes and native audit hashes. Dispatch identity
changes do not create a new logical issue or allowance.

The inventory is evidence accounting, not a semantic correction or an approval.
`revision_required` is an observed opinion, not a confirmed generation defect.
A refusal has an actual reason; it must not be relabeled as execution unknown.
Missing completion proof neither proves no-call nor authorizes replay. Historical
unknown ordinals stay visible even if a separately authorized later response exists.

Compare the earliest divergence: original document → conversion/registered
hash-valid asset → authorized actual wire → citation candidate → page → review.
Required usable evidence omitted from the wire is a program assembly defect;
unusable conversion with no registered substitute is a source limitation. Clear
evidence sent but misrepresented is a generation issue. Misread evidence or an
inconsistent review is a review dispute. Keep hypotheses pending until evidence
supports the cause; record primary cause and downstream effects separately.
Reading-package context cropping is not proof of skipped plan coverage. The
authoritative coverage ledger and required dependency inspections decide coverage.

In the observation phase source conversion and model content issues are recorded
and deferred. Do not reconvert unchanged sources, manually patch domain outputs,
request per-item model correction, or overwrite old responses. Continue evaluation
of other pages. The ready manifest is a durable preparation result, not a page
commit. Existing unified Finalize submission requires all pages in a run to have
valid reviews; deferrals cannot be converted into approval or removed from that
run by this contract. Mixed runs remain held for submission and downstream
coverage/publication; this is reported explicitly rather than claimed as complete.

For identical logical work with unchanged evidence, actual request and failure,
new retry allowance is zero. A new task ID, reason wording or operation ID is not
new evidence. Reopening requires a verified general program fix plus affected
input differences, materially improved hash-valid evidence, authenticated existing
completion, or an explicit supported disposition with new evidence. An inventory
alone grants no calls. After a changed-input correction, check only affected work;
keep valid preparation, plans, Passes, drafts and approved responses. Use at most
one authorized bounded attempt and stop on repeated identical failure or unknown.

`build-native/v1` still authenticates current historical responses and supports
its exact finite unknown-call grants; it does not authorize Finalize content
revision. Pre-Build citation revision is not valid after Build consumption. A
future partial canonical submission/revision contract must handle per-page
identity/provenance, source completion isolation, recovery after registry changes,
and release gap propagation before it may commit part of a mixed run. The
inventory intentionally does not bypass these contracts.
