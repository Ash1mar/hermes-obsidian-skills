# Single semantic generation for new tests

New unconsumed workflows in a test security domain with Query disabled pin
`generation-only-page-semantics/v1` by default. This also applies to a supported
same-workflow test that retires downstream work and creates a new presentation
pin before page writing. Starting an observer or resuming old results does not
change their contract. A test entry reusing an existing consumed presentation or
Build run keeps that old policy; it must not relabel old negative/unknown reviews.

The generation model receives each claim's complete authorized originals, scope,
applicable objects, conditions, exceptions, contrary context, QA and required
assets. Its instructions explicitly require preserving these distinctions before
returning the page. No independent Build model call, risk-triggered semantic
retry, or automatic model revision occurs under the new test policy. Both single
and paired review dispatch are fenced before the native API call.

Build keeps identity/hash checks, citation/source bindings, required evidence,
QA, business/visibility and release eligibility checks. Risk reasons remain
recorded. Acceptance says `independent_review: not_performed`, has no native
review audit/approval, and is tied to the immutable policy captured when the Build
run was created. Full and partial publication use the same core validation.
Program validation establishes its mechanical scope, not semantic correctness.

The optional immutable scope execution field `independent_page_review` accepts
`enabled` or `disabled`; explicit disabling is limited to Query-disabled test
Vaults. Production defaults retain their existing risk-triggered policy. Existing
pins, native responses, review receipts, deferred issues and cumulative budgets
are not migrated. The same-workflow test operator must still follow its stopped,
identity-bound reentry and preserved-history rules.

The fourth supplement's22 reviews (reported91395 input tokens) and4 negative
opinions are read-only comparison samples, not confirmed errors or a prediction
of four extra wrong publications. Holding all other calls constant removes22 of
102 requests (21.57%). Actual next-run pages, calls, tokens, quality, exclusions,
waiting and program overhead require separately authorized native execution.
No workflow is started by installing this policy.
