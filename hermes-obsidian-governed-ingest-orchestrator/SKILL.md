# Governed ingest orchestration

Use this Skill for one-request, recoverable ingest. For request fields and revisions read `references/workflow-contract.md`; for operator actions read `references/operations.md`; for node/worker boundaries read `references/worker-contracts.md`. When a user brings an old three- or six-stage prompt, read `references/compatibility-profiles.md`. Do not copy a six-part prompt into one conversation or use an interactive session as a background worker.

Call `python3 "<skill-dir>/scripts/dispatch_ingest_workflow.py" --vault "<vault>" start --request "<json-file>"` once. The script creates the Vault workflow, pins all twelve versioned templates by SHA-256 and attempts Kanban projection. On retry, use the same request and workflow ID. `dispatcher_unavailable` means the workflow exists but background dispatch is false; report that honestly and resume when Hermes Gateway is available.

For staged execution use `scope.execution_mode: auto_full` and `scope.pause_after` from `references/operations.md`. These are Vault-authoritative stops after exact planning, eight canary slices, all Pass, each verified checkpoint, Build Finalize, and release/Provider sync. Inspect `status.pause` before every recovery or continuation. `resume`, `sync` and a restarted Gateway never release a pause. Only an explicit user request to continue authorizes the trusted operator's `continue-workflow` command, naming the observed boundary, evidence digest and a stable continuation ID. It revalidates the saved evidence and releases exactly that boundary. A worker cannot continue the workflow. Report changed evidence or ambiguous workflow selection; do not start a replacement or edit the ledger.

For status use `python3 "<skill-dir>/scripts/manage_ingest_workflow.py" --vault "<vault>" status --workflow-id "<id>" --compact --runtime`. For resume/cancel use dispatch script commands. In `scope.execution_mode: auto_full`, the dispatcher arms exactly eight ready Pass slices, verifies all eight, promotes remaining slices, and dispatches the downstream graph. Each checkpoint writes a validation report and a hashed decision record. The workflow service independently rechecks the evidence before recording `hermes:auto` approval and continuing. A failed check stops the affected card and reports the blocking codes. In manual mode an explicit human approval remains required. Use current revision and a complete mutation digest for every state change. Never edit workflow JSON or pinned snapshots by hand.

When native tools are installed, prefer `ingest_workflow_status` for compact counts and `ingest_control_workflow` for an explicitly user-authorized resume/cancel. The adapter obtains current identity, revision and digest; use a stable operation_id and retain its receipt. Do not reconstruct requests or inspect implementations for routine control. These tools neither start a replacement workflow nor release a pause. Details and bound-worker input/completion tools are in `references/typed-pass-submission.md`.

`config/orchestration.json` creates one `source-prepare` card per scoped Vault source and releases at most `source_prepare_concurrency` (default two) unfinished, nonfailed source cards at a time. New cards start blocked until the complete graph is bound in the Vault. Completion or failure releases the next source card. Local PDF conversion also uses the controlled-ingest Skill's shared MinerU supervisor; never bypass it with direct MinerU calls. `exact-plan` runs only after every source has a durable ready or failed outcome and at least one is ready. A failed extraction closes only that source card and remains an explicit coverage gap. Exact planning excludes failed sources and covers ready UnitSets; final acceptance is `partial` while source gaps remain. In `auto_full` the dispatcher proceeds through Pass, Reduce, both checkpoints, Build Finalize, release planning and apply, optional Provider sync, and acceptance. Each worker calls `worker-begin` before work and `worker-complete` after durable Vault results; the adapter validates parent outcomes and pinned hashes. Worker commands never mutate Kanban from the isolated terminal. The trusted workflow reconciler started by `start` or `resume` acknowledges cards and dispatches successors from Vault state. If it stops, restart it outside a worker with `python3 "<skill-dir>/scripts/watch_ingest_workflow.py" --vault "<vault>" --workflow-id "<id>"`. The Vault ledger remains authoritative; Kanban is rebuildable.

For a trial that must stop after eight slices, set `scope.execution_mode: canary_only`. Source preparation and exact planning still run for the full requested source scope; only the eight selected Pass slices execute. Completion writes a canary report and does not promote remaining slices or dispatch Reduce. `auto_full` explicitly authorizes continuation beyond the canary.

Legacy preparation workers execute the card's complete `worker_command` once. It runs `python3 "<skill-dir>/scripts/run_preparation_worker.py" --vault "<vault>" --binding "<dispatcher-artifact>"`; the helper reads canonical `template_hash` and task identity and owns begin/check/complete. The model must not generate request JSON or pre-check ordering. Missing fields produce INVALID_SCHEMA; a verified different hash produces STALE_INPUT. Current failed bindings and dependent nodes are archived by the trusted reconciler and domain writes reject EXECUTION_BLOCKED. Block/unblock is not a supported repair. A stopped pre-batch binding requires the operator repair below. Existing template snapshots remain immutable. Same bindings and request artifacts do not change ledger revision. Runtime status reads native attempts separately from source coverage, including connection failures and waiting retries; exit 75 alone is not evidence of quota exhaustion. Whole-workflow coverage is progress, not the card's assigned source.

For a cancelled pre-batch workflow with a proven erroneous failed-source outcome or obsolete pinned contracts, use the operator-only `repair-preparation` operation in `references/operations.md`. Never edit the ledger manually or reuse a failed workflow by changing IDs. Repair preserves a before snapshot, installs a new immutable template pack, invalidates old card bindings and leaves the workflow cancelled until explicit resume.

For semantic problems in completed Pass evidence at a held canary/pass boundary, use the operator-only append revision contract in `references/pass-revisions.md`. `revise-passes` authorizes only selected tasks without releasing the pause. Native workers append replacement citations; original Passes and other valid results remain. Wait for explicit reviewer acceptance using `accept-pass-revision` before any separately authorized continuation. Do not repair this state through preparation reset, re-planning, replacement workflows or ledger edits.

For an explicitly authorized input-size or packaging improvement in a cancelled Pass batch, read `references/compact-execution.md`. Use `prepare_execution_amendment.py`, review `amend-execution --dry-run`, then apply the same saved request. This preserves canonical tasks, completed results and pause history and installs compact inputs only for unfinished slices. It never resumes or releases a pause. Unknown/stale evidence, active native consumers and incomplete revision review block the amendment. Interrupted commits require the same saved request through the supported recovery path.

For typed native semantic submission, fused preflight/persistence and explicit unchanged citation confirmation, read `references/typed-pass-submission.md`. Native workers retain every semantic decision; the adapter handles identities, binding renewal and durable audit records. This installation does not update a workflow's pinned snapshots or authorize resuming it.

New workflows use native program workers for deterministic nodes; read `references/program-execution.md`. Pass, resource/global Reduce and page review use fixed semantic phases described in `references/fixed-semantic.md`: the program owns materials, schema, identity expansion and lifecycle; native model sessions only produce semantic JSON. Normal fixed tasks require no search tools, full Skill reads, long digest copying, request assembly or model-directed retries. Legacy workflows retain their pinned contracts; installation does not silently migrate them.
