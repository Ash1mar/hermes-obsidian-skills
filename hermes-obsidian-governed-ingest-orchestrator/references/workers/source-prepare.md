# source-prepare · v3

- Dispatcher: use the absolute `dispatcher_script` from the card: `python3 "<dispatcher_script>" --vault "<vault>" <worker-command> --request "<request.json>"`. Never resolve a bare filename or select another Skill's dispatcher. In request JSON copy `workflow_id` and `node` from `worker_request`, and `task_id` from this card / `HERMES_KANBAN_TASK`; after begin include the returned `template_hash`.
- Stop immediately on failed worker-check or heartbeat, cancellation, stale binding or template mismatch. Do not import internal services to bypass a failed command, resume/cancel the whole workflow, alter pinned contracts, or clear worker environment variables. Report runtime/contract failures on this card; they are not evidence of damaged source material.

- Sole objective: prepare exactly `worker-begin.assigned_source`. Its path and SHA-256 define this card's scope. `source_coverage` is read-only progress for the whole workflow, so multiple requested sources there are expected and are not a SCOPE_MISMATCH.
- Call `worker-begin`, then `worker-register-source` through the dispatcher. The latter reuses an existing same-content identity or allocates deterministic document/version/resource IDs and an unresolved candidate organization. These are technical identifiers, not invented business versions or approvals. Use the returned identities and begin's actor in domain commands. Keep unknown business metadata unknown; do not activate or approve sources.
- Use controlled-ingest registration/conversion/quality/SourceUnit commands for only this source; inspect their `--help` and the Skill before invocation. Follow the Skill's conversion retry rule. Preserve conversion QA and evidence. Heartbeat before and during long work. Check again before domain commits.
- Governance mutations and SourceUnit publication verify the current workflow binding under its cancellation lock. A conversion already in progress may finish temporary output after cancellation; do not register or publish it then. Never remove worker environment to bypass this guard.
- Call `worker-complete` with resource ID and UnitSet ID only after validated current SourceUnit publication. A real exhausted source error uses `worker-fail` with PDF_UNREADABLE, CONVERSION_FAILED, UNSUPPORTED_FORMAT, BUNDLE_VALIDATION_FAILED or SOURCE_UNIT_VALIDATION_FAILED, a specific reason and existing QA artifact references. This closes only this source as a coverage gap; other sources continue.
- Entry-point, scope interpretation, missing identity, contract, ownership and cancellation errors must not be classified as damaged PDF. Report the actual code through `worker-fail` when the worker check is still valid; otherwise stop with the failed command evidence. Never call record_source_outcome directly.
- Bounds: one source; no neighboring files, whole-Vault crawl, exact planning, Pass/Reduce/Finalize, or checkpoint approval. Never call an unreadable PDF a ready SourceUnit or a section-ledger skipped item.
- Output: {"ok":boolean,"workflow_id":string,"node":string,"source":string,"artifact_refs":string[],"quality":string,"error_code":string|null}.
