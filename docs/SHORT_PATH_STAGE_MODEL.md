# 短路径五阶段与术语约定

记录日期：2026-11-09。适用于主题—原文证据映射短路径的流程说明、运行报告和维护讨论；历史流程仍按其固定合同解释。

**五阶段架构保持，Pass 与 Reduce 改用主题—证据映射短路径；模型职责更集中，程序负责更多组包、绑定、验收和交付工作。** 对外继续使用 Exact-plan、Pass／Map、Reduce、Finalize、Release & Provider sync，并保留 slice 术语。

业务阶段名称、内部任务和恢复入口属于不同层次。名称沿用不代表旧候选、旧切片和新映射回执可以互换，也不表示新增了同名 CLI 参数。

## 五阶段与当前实现

| 阶段 | 短路径职责 | 当前实现及边界 |
| --- | --- | --- |
| **Exact-plan** | 核验来源、版本和完整材料范围，确定初始请求分包与预算。后续随主题、页面计划继续计算真实请求体量。 | 独立 post-MinerU 入口在旧工作流的 `exact_plan` 持久边界取得来源交接；短路径另行生成请求计划，不沿用旧 Candidate 任务计划。这里的业务划分不等于旧图中同名节点的全部执行细节。 |
| **Pass／Map** | 提取初始主题，关联原文、条件、例外、必要上下文及资产，记录关联、排除和待处理状态。 | 包含 `short-topics`、`short-map` 及按需局部处理。映射允许补充主题；正常路径不再执行独立全量 Citation 核对。 |
| **Reduce** | 汇总主题映射，协调页面身份、范围和边界，展开完整证据，按预算组包写作并合并片段。 | 包含 `coordination` 和 `writing`。取消常规 Resource Reduce 的重复归组；语义协调和写作仍由模型承担。 |
| **Finalize** | 验收和组装页面，执行正式 Build，提交页面版本，绑定证据、覆盖证明、隔离记录和 QA 标注。 | 通过短路径原生凭据接入正式 Build。程序验收不等于独立语义审查；新路径记录独立模型审查未执行。 |
| **Release & Provider sync** | 判断精确候选的发布资格，完成部分发布、Provider 索引同步及发布与索引一致性核验。 | 发布只包含合格页面及版本；索引匹配对应 release。Provider 同步与 Query 启用是不同操作。 |

当前独立入口的执行衔接为：来源准备及交接 → 短路径原生板 → 正式 Build 和版本提交 → 发布 → Provider 同步及最终验收。

相关实现：[独立入口](../hermes-obsidian-governed-ingest-orchestrator/scripts/start_post_mineru_short_test.py)、[请求规划](../hermes-obsidian-governed-ingest-orchestrator/scripts/prepare_short_evidence_test.py)、[正式 Build 与发布适配](../hermes-obsidian-governed-ingest-orchestrator/lib/short_formal_build.py)。

## Pass 与 slice 的含义

- **Pass** 是前置理解阶段。旧 Pass 交付详细候选及 Citation 核对记录；新 Pass 交付主题—原文证据映射。沿用名称不恢复被取消的模型检查。
- **slice** 是 Pass 中具有明确材料范围、预算和结果身份的处理切片。新路径中可用它描述映射处理范围，不再默认一个切片必含 Candidate 和 Citation 两轮。实际任务 ID、请求 ID 和回执仍按运行合同记录，不能把名称相同当作身份等价。
- **知识页** 是有独立读者问题和范围的逻辑交付单元。
- **写作片段** 是某个知识页内的一部分写作职责。同一主题或页面可以跨多个片段；条件、例外和完整资产依赖应随对应片段提供。
- **模型请求** 是一次实际调用，可承载一个或多个被支持的独立任务槽。业务阶段、slice、片段和模型请求的数量不必相等；当前写页组包最多两个槽。

预算导致请求分包，不自动意味着新增知识页。所需片段没有全部合格时，不能删除失败片段后将剩余正文作为原完整页发布。

## 模型与程序的职责

| 工作 | 旧链路 | 短路径 |
| --- | --- | --- |
| 前置理解 | Candidate 详细表达事实、适用范围、条件和例外，Citation 再核对候选与原文。 | 模型识别主题及证据关系，详细表达集中在写页。程序校验编号、来源绑定和材料去向。 |
| 归组与规划 | Resource Reduce、Global Plan／Detail 分层组织候选与页面。 | 程序汇总明确映射，模型处理语义边界、冲突和歧义；程序计算体量并机械分包。 |
| 写页与交付 | 写页模型生成正文，后续按各历史固定策略执行 Build 和发布。 | 模型依据完整授权材料写页；程序检查结构、引用绑定、必读资产、覆盖记录、版本和发布资格。 |

程序能够检查材料是否供给、编号是否有效、去向是否齐全，不能由这些检查证明条件、例外已经被正确理解。保留已确认的内容错误及其直接依赖隔离，其他合格结果继续部分交付。

本 workspace 的来源 QA 是标注：保留原始标签、范围、依据和不确定性，不由用户或 Codex 签署专业 QA 结论。单独的来源级或未定位 QA 标签不阻断合格页面；具体必需证据、身份、来源绑定或实质内容失败仍影响其直接依赖。

## 恢复入口与历史兼容

当前 `run_short_evidence_test.py reenter --from-node` 支持 `mapping`、`coordination`、`writing`。其中 `mapping` 是映射恢复入口，不能把它理解为必然重跑初始主题提取；实际复用由前序回执和输入检查决定。正式 Build 和交付另走 `formal` 等受支持入口。

这三个入口覆盖中间处理过程，并不是 Exact-plan、Map、Reduce、Finalize 的一一改名。五阶段名称用于流程组织与报告，不宣称已经提供五个统一的 `--from-node` 参数。

恢复时核对当前来源身份、哈希、输入及合同版本，复用有效结果，保留原请求、失败回执、隔离和累计调用账目。旧候选不能作为新映射回执使用；旧 slice 不能仅凭名称进入新合同。名称统一也不释放暂停、不授权重试、发布或 Provider 同步。

具体命令和版本边界见[短路径操作说明](../hermes-obsidian-governed-ingest-orchestrator/references/short-evidence-test.md)及[运行入口](../hermes-obsidian-governed-ingest-orchestrator/scripts/run_short_evidence_test.py)。

## 与 WeKnora MapReduce 的关系

此前对照的 WeKnora Wiki 实现也采用主题提取及原文块映射，再按主题汇集材料生成或更新页面；外围还有来源处理、目录规划、摘要和索引工作。这里的 MapReduce 描述核心知识构建方式，不表示整个系统只有两个阶段。

Hermes 的五阶段还明确包含正式版本提交、部分发布与 Provider 同步。因此，“采用 MapReduce 的短路径”和“保留五阶段流程”可以同时成立；两者并不意味着审查、资产处理、失败隔离和发布资格合同完全相同。WeKnora 对照是设计背景，不是 Hermes 的运行依赖或验收标准。

## 报告口径

按五阶段报告进度，同时保留内部任务或请求标识。实际调用、输入输出 token、重试和耗时按发生阶段记录；一次性质量对照单列，不能算成日常 Build 模型审查。

五阶段业务主线保持，不代表内部没有重构：Pass 中间产物、Reduce 组织方式、原生凭据和恢复衔接均已改变。引用数量、页数和调用数不能单独证明质量或效率提升；比较应同时检查实际内容覆盖、具体错误、保留缺口和累计成本。
